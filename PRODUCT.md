# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The repo owner (izel), working solo. This is a personal design playground: each experiment's imagined end user is defined per experiment, but the only real audience evaluating the work is the owner.

## Product Purpose

A sandbox repository for UI experiments and prototypes — not a single product. Success for any piece of work here is that it teaches something or looks/feels exceptional, not that it ships to production. Work targets responsive web, desktop and mobile treated equally (the repo name "mobile-scratchpad" is historical, not a platform constraint).

## Operating Context

Experiments live side by side in this repo. Each experiment should be self-contained (its own directory or file) so unrelated prototypes never entangle. Work is driven through Claude Code sessions, often from mobile, so prototypes should be viewable as static files or with a trivial dev server.

## Capabilities and Constraints

- No build system, framework, or dev server exists yet; each experiment chooses its own stack, defaulting to dependency-free static HTML/CSS/JS unless the experiment demands more.
- No fixed product domain: subject matter is decided per experiment at request time.
- Undecided: whether any experiment will later graduate into a real product (record that decision here if it happens).

## Evidence on Hand

None. There are no real users, testimonials, metrics, customers, or brand assets. Prototypes must not fabricate real-sounding proof (fake customer logos, invented press quotes, made-up statistics presented as real); clearly-fictional placeholder content within an experiment's own fiction is fine.

## Product Principles

- Each experiment is a fresh canvas: no shared visual world is assumed across experiments unless one is deliberately extracted later.
- Bias toward finished-feeling vertical slices over broad half-built scaffolds — the point is craft, not coverage.
- Keep experiments throwaway-cheap: self-contained, dependency-light, deletable without ceremony.
- Since the audience is the owner, be bold by default; safe/generic output has no value here.
